What the arrows enforce

  1. One direction only. api → knowledge, always. knowledge never calls api and never reads its tables — it only receives pushed payloads at /v0/quality/*.
  2. The browser has one door. It reaches web and api only — never knowledge directly, in dev or in production.
  3. One database, two locked roles. api_rw and knowledge_rw each see only their own tables — no shared views, no cross-schema SELECT in either direction.
